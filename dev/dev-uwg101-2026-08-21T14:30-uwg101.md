## Goal

The pure detection half of the usage-window governor: recognise a usage-limit
exhaustion in worker output, and parse the window reset time out of it.

Ships **inert** — nothing calls it. That is deliberate (design.md § Phase 1,
the mss101 shape): the module is pure, so its whole contract is unit-testable,
and shipping it uncalled means Phase 2's review can be about the driver seam
rather than about regex semantics.

## Acceptance criteria

- [ ] AC 1: `src/lib/loop/usage-window.ts` exports `USAGE_LIMIT_MARKERS`
      (non-empty `RegExp[]` covering the known shapes: `claude (ai|code)?
      usage limit reached`, `N-hour limit reached`, reset-suffixed variants),
      `firstUsageMarkerInTail(raw, tailBytes)`, `parseResetTime(raw, now)`
      and `detectUsageWindowHit(input)`.
- [ ] AC 2: **Tail-bounded.** A marker outside the scan tail is invisible —
      mirrors `firstPermanentErrorMatchInTail` (`ladder.ts:116-122`), which
      is already review-hardened. Do not invent a second posture.
- [ ] AC 3: **Corroboration required (E-2, P0).** A tail marker is a hit only
      when the iteration ALSO failed to produce a valid trailing report (or
      exited non-zero). A transcript that merely mentions the string and ends
      with a valid report classifies as SUCCESS. This fires whenever someone
      edits this module's own source, so it is not hypothetical.
- [ ] AC 4: `parseResetTime` handles the unix-epoch `|<ts>` suffix, the
      wall-clock next-occurrence form ("resets 3am"), and ISO-8601. **A
      parsed time in the PAST returns null** — a stale reset must never
      produce a zero-length pause that spins.
- [ ] AC 5: The RED artifact `test/loop-usage-window.test.ts` E-2 block +
      `parseResetTime` block go GREEN. Re-run them RED first and confirm they
      fail for the stated reason (the module is missing), not because the
      harness is broken.
- [ ] AC 6: Nothing imports the module yet — grep-verified. Full suite green.

## Technical notes

- Marker discipline: `ladder.ts`'s `PERMANENT_ERROR_MARKERS` is the model.
- The marker set is SEEDED, not observed (design.md § Risks). The
  corroboration rule is what makes a too-narrow set fail safe — a missed
  marker degrades to today's behavior. A too-WIDE set is the dangerous
  direction, which is why AC 3 is the P0.
- Review shape: marker-bearing regex surface → **3-agent parallel regardless
  of line count** (LEARN marker-discipline pattern).

  timestamp. `dev/dev-uwg101-2026-08-21T14:30-uwg101.md` sitting 20KB before

  into the wall. Fixed by anchoring the parse in a window around the matched
  marker (`RESET_SCAN_CHARS`).
  Other findings, all fixed in-place: the corroboration rule was incoherent
  in both directions — `exitCode` overrode a valid report (STRICTER than the
  driver's own `classifyIteration`, so the governor could pause an iteration
  the driver calls healthy) while `report.success === false` was ignored (so
  a reported failure naming a real limit rode the reported-failure ladder,
  E-1's exact failure mode); it is now one sentence, "a report claiming
  success clears the hit, nothing else does", matching the driver.
  `parseResetTime`'s branches returned unconditionally, so one stale epoch
  discarded a good wall-clock reset after it. `tailChars: 0` scanned the
  WHOLE transcript (`slice(-0) === slice(0)`) — the natural spelling of
  "disable" maximised the false-positive surface. Non-string input threw.
  `USAGE_TAIL_BYTES` never meant bytes (renamed; the alias is kept and
  documented rather than silently narrowing the window for non-ASCII
  transcripts). Markers were returned in list order rather than by position,
  degrading the corpus evidence. The separator class omitted the en-dash.
  Test-side: the one positive-hit case used a STALE 2025 epoch and asserted
  only `not.toBeNull()`, so nothing in the suite ever observed
  `source: "parsed"` — deleting the parse call entirely would have kept every
  test green. The wall-clock case asserted only `> NOW`, so a mutation
  turning 6am into 6pm stayed green. Assertions went 10 → 16, including a
  full corroboration truth table and a regression test built from the HIGH's
  actual repro.
