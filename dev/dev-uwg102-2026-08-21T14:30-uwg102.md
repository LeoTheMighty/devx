## Goal

Pause the loop on a usage-window hit and resume the same item, intercepting
**before** the ladder is consulted.

## Acceptance criteria

- [ ] AC 1: `src/lib/loop/usage-governor.ts` exports pure
      `planPause(hit, cfg, ctx)` and impure `runPause(plan, deps)`. Every
      bound lives in `planPause` so it is testable without a clock.
- [ ] AC 2: **D-UW1 — `src/lib/loop/ladder.ts` has ZERO diff.** The
      interception sits in `driver.ts`'s `runItem`, before
      `classifyIteration`. Assertable; the reviewer should check it.
- [ ] AC 3: E-1 (P0) — a hit pauses; the SAME item resumes after the fake
      clock passes reset; `consecutiveFailures`/`consecutiveErrors`/
      `consecutiveAbandonedItems` all stay 0; the interrupted iteration is
      not charged against `maxIterationsPerItem`; `pendingRepair` survives;
      no `[FAIL]`/`[ERROR]` status-log lines; loop exits 0.
- [ ] AC 4: E-3 — unknown reset → probe cadence at
      `usage_probe_interval_ms`; cumulative pause > `usage_max_pause_ms` →
      clean abort naming the weekly limit.
- [ ] AC 5: E-6 — a reset landing after the `--until` deadline takes the
      ordinary deadline path. The loop must never hold a machine past the
      hour its operator named.
- [ ] AC 6: E-5 — `resume_on_reset: false` is checked FIRST, short-circuiting
      before any governor code runs, so today's behavior is restored by
      construction rather than by matching.
- [ ] AC 7: `runPause` sleeps in CHUNKS, re-checking wall-clock each time —
      a single long sleep cannot self-correct after a machine suspend
      (`project_devx_loop_sleep_kills_iterations`).
- [ ] AC 8: Full suite green.
