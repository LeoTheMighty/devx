## Goal

A pause that leaves no trace is indistinguishable from a hang. Make it
visible in every surface that shows a run's state.

## Acceptance criteria

- [ ] AC 1: `LoopStatus` gains `"paused"`; `src/lib/next/gather.ts`'s
      liveness predicate widens from `status === "running"` to
      `running | paused` (E-4). A paused loop is ALIVE — reporting it
      crashed is how a human kills a run that was working. Age-based
      staleness is unchanged: paused-and-stale still reads dead.
- [ ] AC 2: The heartbeat keeps beating during the pause (the chunked sleep
      is the natural beat point).
- [ ] AC 3: `RunSummary` gains `windowPauses: PauseSegment[]`
      (`startedAt`, `endedAt`, `resetSource: "parsed"|"probe"`,
      `durationMs`); the morning report gains a **Usage-window pauses**
      section plus total paused time in the header (G-3).
- [ ] AC 4: Four `loop:` knobs — `resume_on_reset: true`,
      `usage_probe_interval_ms: 900000`, `usage_max_pause_ms: 21600000`,
      `usage_reset_slack_ms: 60000` — in **both** `src/lib/loop/config.ts`
      AND `_devx/config-schema.json`. The schema block is
      `additionalProperties: false`, so a knob added to one and not the
      other makes config load REJECT the setting it added. Two files, one
      change.
- [ ] AC 5: FR-7 honesty pass — `probeUsage()` ships inert returning null;
      the `devx.config.yaml` comment, `docs/CONFIG.md` §2 and §15b, and the
      morning report all say plainly that `usage_cap_pct` is NOT enforced
      today. No code path may branch on it in a way that would silently
      start enforcing it. Also drop CONFIG.md §2's stale dollar-cap rows
      (removed at INTERVIEW Q#6).
- [ ] AC 6: Full suite green.

## Technical notes

- Grouped rather than split because these are one concern: splitting them
  would ship a `LoopStatus` value that `gather` rejects.
