## Findings

### F1 — [high] [docs+skill] A design premise can be false, and the review is where you find out

mss102's design said "specs without `branch:` (all existing specs) take the
derive path." That premise was **false**: `validate-emit` requires every
emitted spec to record its own derived branch, so the attach arm would have
fired on *ordinary* claims and silently adopted a leftover same-named branch
(crashed loop run, closed-not-merged PR) where the claim previously failed
loudly at `worktree add -b`.

Two of three reviewers flagged it independently. The author narrowed
inheritance to `recorded != derived` and filed **INTERVIEW Q#14** with
options rather than deciding silently — which is the behaviour CLAUDE.md's
"no silent product decisions" rule asks for, executed under time pressure at
22:00 on a four-phase evening.

The generalizable part is not "check your premises." It is that a premise
about the *existing corpus* ("all existing specs look like X") is checkable
mechanically in seconds and is exactly the kind of thing a design stage
asserts without checking. — pending: worth a `/devx-plan` design-stage prompt
line ("for every claim about what existing artifacts look like, name the
command that verifies it").

### F2 — [high] [code] A behaviour change that reroutes a failure path must re-home the guarantees the old path carried

mss103 changed budget exhaustion **with real committed progress** from
abandon to split. Four pre-existing loop-driver tests encoded the old
contract. Three were retargeted keeping every accounting assertion; the
fourth (MED-4) was rerouted to the failure-ladder abandon path *where its
guarantee is still reachable*, and additionally asserts no `item:split`
fired.

The load-bearing review finding, found independently by two reviewers: the
budget rail routed a commit-failure-preserved **dirty** worktree into the
split, where `worktree remove --force` destroyed work `pushCurrentBranch`
never committed — a strict work-loss regression versus the abandon path it
replaced. Closed by `hasCommittedProgress()`, which also gates the worker
path so the advisory clean-seam claim is *verified, not trusted*.

"Verified, not trusted" is the reusable half. A worker-supplied assertion
about its own state is an input, not a fact. — applied in mss103.

### F3 — [med] [docs] A retired test-only lock must be ported to its successor in the same PR

dvx107's `parseHandoffSnippet` pinned skill-body prose that mss104 deleted.
Deleting the validator alone would have silently un-pinned Phase 9 at the
exact moment its contract changed.
`test/devx-skill-phase9-split.test.ts` carries `phase9Body()` across
verbatim — including the load-bearing `^(### |## )` bound, itself a dvx107
review finding.

This was already recorded as candidate C2 on 2026-07-29 and applied in PR
#101. Promoting the *shape* rather than the instance: when a PR deletes a
guard, the PR must name its successor. — applied; sub-pattern concordance
deliberately left at 1 epic (a successor to the same lock is not an
independent observation).

### F4 — [med] [docs] When a phase carries a mechanical eval, the eval's scan scope IS the acceptance surface

mss104's ACs 1–4 named the files to sweep, but E-2 greps all of
`.claude/commands/`, `src/`, `test/`, `docs/`, `v2/` — and two stale comment
tokens in `src/lib/devx/split.ts` kept the eval RED while appearing in no AC.
The choice at execute time was to widen the sweep or narrow the eval;
narrowing a permanent invariant to match an incomplete AC list would have
been the wrong trade.

Candidate C1 from 2026-07-29, confirmed here. Generalization for
`/devx-plan`: derive the AC file list *from* the eval's scope, or state
explicitly that the eval is authoritative and the AC list illustrative. —
pending: a `/devx-plan` Plan-stage line.

### F5 — [med] [miss] The epic's own bookkeeping was swept into a peer's commit — and the fix took three more weeks

mss104's status-log lines were swept onto `main` by a concurrent session's
`git add -A` (commit `ac0ccf2`, erratum recorded in `ba3c65b`). Content
intact; authorship wrong.

This is the E1 class that `multi-loop-concurrency` had *already* recorded,
and it recurred **during this epic** because the structural fix did not
exist yet. It was finally closed on 2026-08-21 by `b931a1`'s `finalize`
primitive, which stages exactly the pathspecs `mark-done` returns — 24 days
after this epic observed it a second time.

Tagged `(miss)` deliberately: the lesson is not "don't use `git add -A`",
which was already written in two places. It is that **a rule stated in prose
and violated twice is evidence the rule needs a mechanism, and the gap
between those two facts was three weeks of exposure.** — applied elsewhere
(b931a1, PR #138).

### F6 — [low] [miss] A retro run 23 days late is a different artifact than one run at close

mss101–mss104 merged 07-28/07-29; this retro ran 08-21. In between, three
of its findings were independently rediscovered and fixed by later work
(F5 by b931a1; the split-lock ordering by mss104's own review). The retro's
value here is mostly *archival* — recording that the system caught these
things twice, by different routes.

The `*ret` item sat `ready` and unblocked in DEV.md the whole time, and
`devx next` never surfaced it above other work. — filed: worth considering
whether a `*ret` item older than N days should raise a dispatcher row.
