## What worked

**The hardened paths held under the first real concurrent load.** This
epic and `mid-story-split` ran interleaved across 2026-07-28→29 — eleven
PRs (#91–#101) merged in ~24h across the two epics, a concurrent
`/devx-learn` run, and a third session live on `lpf101`. Across all of it,
**not one status log, report, or erratum records a lost backlog update, a
corrupted DEV.md, a claim collision, or a spec-lock stomp** — the four
failure classes Layer 1 was built to kill. That is an
absence-of-recorded-incident claim rather than an audit, but it is the
strongest evidence available and it is unstaged: nobody arranged this
concurrency, it just happened while both epics were in flight.

Method, so the claim can be re-checked: grepped every `mlc*`/`mss*` spec
for lost-update/clobber/stomp/overwrite/collision language (all hits are
design prose about the problem being *solved*, plus mss101's backlog-row
parser-marker collisions — no incident reports), and listed every repair-shaped commit in
the window. There are exactly two, `ba3c65b` and `fb7561f`, and both are
bookkeeping-tail defects (E1). No commit repairs a lost backlog update or a
corrupted state file.

Worth stating precisely because the contrast is the whole point: the
cross-session defects that *did* occur in this window — three of them —
were all in the bookkeeping tail (see E1), not in the locked paths.

**Sequencing the phases so each one's RED artifact was honestly red.**
Every story re-ran its eval before writing code and checked the failure
*reason*, not just the exit code — mlc101 caught its own eval infra lying
(the `_fixture.ts` tsx path didn't resolve in linked worktrees, so the CLI
under test never spawned and the "refusal missing" assertion never ran),
fixed the harness, and re-confirmed an honest RED. mlc106 captured the E-8
byte-identical dry-run baseline *before* touching anything and re-diffed
after. This is the RED-reason discipline that PR #92 folded into the skill
mid-epic, and it paid immediately.

**Adversarial review kept catching load-bearing semantics, not lint.**
The ten HIGHs were all real behavioral defects that tests-as-written would
have shipped: worktree misclassification via path shape (would have
false-refused `devx loop` in submodule and separate-git-dir layouts and
hard-blocked claims with no override); a backlog-lock timeout inside the
composite driver holds aborting the *entire* loop run and stranding a
merged PR unreconciled; an ungated lock reap that would have destroyed a
live peer's claim (the E13 collision class, reintroduced); `isRejectedPush`
over-matching git's generic push trailer so hook/policy refusals would have
routed around the systemic-failure budget and walked the whole backlog as
fake contention; a `".."` session token whose sanitizer returned it
unchanged, pointing a recursive `rmSync` at `.devx-cache` itself; and a
scope intersecting to zero rows that took the lock, spawned nothing, and
wrote a report claiming "0 attempted" with no reason — the precise silent
no-op night `validateScope` exists to prevent.

**Real-repo smoke as a phase-exit ritual.** mlc105 registered five live
instances into the *live* `.devx-cache` and drove the real CLIs against
them; mlc106 smoked all five scope flags against this repo's real 131-row
backlog. Both surfaced things fixtures cannot.

## What didn't

The three findings below are the epic's real cost. All three share a
shape: **the mechanisms this epic converted into code held; the ones still
expressed as prose in the skill body broke.**

### E1 — The after-merge bookkeeping tail is still inline git prose, and it broke on first concurrent contact

mlc106's mark-done commit `ac0ccf2` was staged with `git add -A` and
therefore swept in two files belonging to the *concurrently live* mss104
session — that spec's phase 2/3 status-log lines and
`_devx/workstreams/mid-story-split/todo.md`. The content landed intact, so
the damage was attribution rather than loss, and the author correctly
declined to revert (backing it out would have deleted a live peer's work
from main). Recorded as an erratum in `ba3c65b`.

The contract it violated is stated twice — `CLAUDE.md` Working agreements
and `.claude/commands/devx.md` Phase 6, both saying *stage only files
relevant to this item, never `git add -A`*. Stating it twice did not help,
because it is prose an agent re-reads under time pressure rather than a
primitive that cannot be called wrong. Contrast every hazard this epic
*did* convert: the claim push race (`claimSpec` rebase-retry), the backlog
mutation race (`withBacklogLock`), the spec-lock race
(`acquireSpecLock`) — all held, unattended, across two live sessions.

It was not the only tail defect in the window. `mss103` appended its phase
2/3/4/5 status lines *after* the spec's `## Links` heading; the dvx103
discipline test deliberately bounds its scan to the `## Status log`
section, so main itself went red for every PR branched off it — mlc106
inherited that red on its first CI run and spent an investigation cycle
proving the failure came from neither its own diff nor its own branch
(repaired on main in `fb7561f`, a pure five-line relocation). Same tail,
same shape: a hand-performed append with no primitive enforcing where it
lands.

So the window produced three distinct bookkeeping-tail defects — an
unscoped stage, a misplaced append, and a skipped lock release (E3) —
against zero defects in the paths this epic converted to code. That ratio
is the finding.

This is a fresh, sharp instance of the promoted cross-epic pattern
*"Externalize behavior-as-CLI-primitive consumed via skill-body
passthrough."* `/devx` Phase 8's after-merge tail is one of the last
inline-git sections left, and it is the one that runs while peers are
live.

The same tail has two adjacent defects, which is why the corrective is one
primitive rather than three patches:

- It never releases the spec lock (see E3).
- It writes the merge status line from narrative rather than the clock
  (see E5).

**Corrective:** `devx devx-helper finalize <hash>` — stage exactly the
known bookkeeping paths (the spec file, the backlog file, nothing else),
release the spec lock under the backlog lock, and stamp the merge line
from the clock. Filed as a dev spec (`dev-b931a1`).

> **Concurrent corrective — merged mid-retro as PR #102 (`8bd514e`).**
> While this retro was being written, a peer `/devx-learn` session shipped
> the *prose + test* half of this fix: an explicit-pathspec staging rule
> added to Phase 8 of both skill-body copies, plus
> `test/devx-skill-phase8-discipline.test.ts` extended to pin the
> `never git add -A` sentence in **both** Phase 6 and Phase 8 so a future
> edit cannot quietly drop either copy. Their note records the sweep as
> having happened **twice**, not once — independent corroboration.
>
> It also caught two adjacent defects this retro had missed, both worth
> recording because they explain *why* the tail is fragile: Phase 8's
> after-merge list was **misnumbered** (1,2,3,4,5,7,8,9) and its commit
> step referenced a range `(4-6)` whose upper bound did not exist, and the
> workstream `todo sync` step was absent entirely. A step list an agent
> cannot follow literally is a step list an agent improvises around — which
> is the mechanism behind all three tail defects above.
>
> The two correctives are complementary and `dev-b931a1` is scoped
> accordingly: theirs makes the rule un-droppable *as prose* and repairs a
> genuinely broken list; b931a1 removes the need to rely on prose at all
> and carries the three defects neither touches (lock release, dist
> rebuild, clock-stamped line).
>
> Worth noting as its own small observation: two sessions independently
> found and acted on the same defect within hours of each other. That is
> the concurrency model working — more eyes, faster — and simultaneously a
> coordination cost, since neither knew the other was on it. The cheap
> mitigation is the one this epic already shipped and neither session used:
> a scoped `devx loop`/claim makes "who is on what" legible in `devx next`.

### E2 — The epic's headline feature is merged and *not installed*

`devx` on PATH resolves to `<repo>/dist/cli.js`. `dist/` is gitignored and
rebuilt only by `npm run build` — and a story's local-CI gate runs inside
its **worktree**, so it builds the *worktree's* `dist/`, never main's.
Main's `dist/cli.js` was last built 2026-07-28 17:04, four minutes after
mlc105 merged and ~16 hours before mlc106 did.

Verified today, on main, at retro time:

```
$ devx loop --help | grep -c epic
0
$ ls dist/lib/loop/scope.js
ls: dist/lib/loop/scope.js: No such file or directory
```

mlc106 — the largest story of the epic (+2,534 lines) and the one carrying
the entire scope model — is invisible to the CLI that `/devx` itself
invokes. An operator opening E-7's checklist tonight would type
`devx loop --epic <slug>` and get commander's `unknown option` — *the exact
error string E-6's RED eval asserted before the feature existed.* The
feature is shipped, tested, merged, and unreachable.

This also retro-explains a smaller anomaly. Spec-lock bodies on disk split
by format: `mlc101`, `mlc103`, `mlc104` are legacy three-line, while
`mlc106`, `mss104`, and this retro's own lock are JSON v1. mlc103 shipped
the JSON format at 12:46; mlc104 claimed at 13:22 and still wrote legacy —
because the claim runs from main's stale `dist/`, not from source. The
format transition tracks main's rebuild time, not the merge.

Every `/devx` claim, gate, and merge decision made between a primitive's
merge and main's next rebuild runs on the *previous* build. For a project
that self-hosts its own tooling this is a correctness surface, not a
convenience one.

**Corrective:** rebuild main's `dist/` as part of the after-merge tail
(natural fit for the E1 `finalize` primitive), plus a cheap staleness
guard — warn when `dist/build-info` is older than `HEAD`. Filed with E1.

### E3 — Spec locks leak at merge; four of six

`.devx-cache/locks/` still holds `spec-mlc101.lock`, `spec-mlc103.lock`,
`spec-mlc104.lock`, `spec-mlc106.lock` — every owner PID long dead, every
spec `done` and merged. `mlc102` and `mlc105` released theirs; both status
logs mention doing it explicitly, which is the tell: it happened because
those two authors thought of it, not because the flow does it.

Reading `/devx` Phase 8's after-merge steps confirms it — pull, remove
worktree, delete branch, update spec, update DEV.md, commit, file gaps,
check epic. **No step releases the spec lock.** The loop driver *does*
(mlc103 shipped `ownsClaim`/guarded release for it); the interactive path
never did.

Harmlessness is real but conditional: mlc103's classifier reaps a
dead-owner lock on the next contending claim, so these never block anyone.
But a `done` spec is never claimed again, so nothing ever triggers the
reap and the files accumulate forever. G-3 says *unreapable* debris, and
these are reapable in principle — the letter holds. The spirit is that the
repo should not need a janitor for state the happy path was supposed to
clean up.

**Corrective:** release in the `finalize` primitive (E1) — but *not* by
writing a new release path. `dev-ee7049` was filed independently during
this retro (from the mss104 gap sweep, `78a10b6`) and ships exactly the
missing piece: a `devx devx-helper release-lock <hash>` CLI wrapping
`releaseSpecLockGuarded`. `b931a1` should consume it. The offline sweep of
already-accumulated debris belongs to `db36af` (`devx doctor`), which
already scopes "stale locks, dead owners" and is unshipped.

The three specs partition cleanly, which is worth stating so nobody
rebuilds a neighbour's half: **ee7049** wraps the one release path that
goes *around* the guarded primitive (Phase 9's raw `rm`); **this finding**
is the one path with *no* release at all (Phase 8); **db36af** collects
what already leaked. Together they close the interactive lock lifecycle
that the loop driver has had since mlc103.

## Also observed

### E4 — The 3-agent shape was unavailable for mlc105, and single-pass under-caught

mlc105 ran a single-pass 3-lens review because that session's harness
forbade spawning subagents. The author recorded it as a deviation rather
than silently single-passing, which is the correct discipline and worth
saying plainly.

The result is still a signal. mlc105 was +1,513 lines across 13 files —
comfortably over the substantial-surface threshold — and returned **4**
findings. Its 3-agent peers on comparable surfaces returned 10, 12, 16,
~20 and 26. It did catch a genuine HIGH (the `".."` scratch-reap path
escape), so this is not a failed review; but a 4-vs-16-median gap on an
above-threshold surface is the shape of under-catching, not of a cleaner
diff.

Environmental unavailability of the parallel shape has now happened twice
(dvx107's 2-agent fallback was the first). Twice is a pattern worth a
named fallback: when the parallel shape is unavailable, compensate —
sequential passes with a context reset between them — rather than
collapsing to one pass and noting it.

### E5 — Status-log timestamps are narrative-authored, not clock-read

mlc106's tail reads `00:20` phase 5/6/7 → `00:35` CI red → `00:45` merged.
The PR actually merged at `2026-07-29T15:24:22Z`, after a re-run that
started at `14:53Z`. So ~15 hours (an overnight pause and a next-morning
CI re-run) are compressed into 25 minutes of narrative, and the timezone
silently switches from local `-06:00` — used by every other line in the
epic — to UTC.

Nothing downstream broke. It matters because retro evidence *is* the
status log; this retro caught it only by cross-checking `gh` and `git log`,
which is exactly the "reconstruct from disk, treat claims as claims"
discipline the morning-review rule already mandates. The cheap structural
fix rides along with E1: the tail already writes the merge line — have the
primitive stamp it.

### E6 — The epic's own plan spec drifted, and `devx next` caught it

`plan-20eb6f` frontmatter says `status: ready` while `PLAN.md` marks the
row `[x]`; `devx next` reports it as a `status-mismatch` drift row.
Surfaced by the tool, as designed, rather than discovered by hand.
Reconciled in this PR (frontmatter → `done`, `stage: retro` → closed).

## Cross-epic promotion review

- **"Externalize behavior-as-CLI-primitive consumed via skill-body
  passthrough"** — reinforced (5th epic). E1 is the sharpest instance yet
  because the counterfactual is inside the same epic: the three hazards
  converted to primitives held under concurrency; the one left as prose
  did not.
- **"3-agent parallel adversarial review on substantial-surface stories"**
  — reinforced (6th epic; 5/6 stories at threshold, ~88 findings). E4 adds
  the *environmental-unavailability* sub-pattern's second instance and a
  concrete under-catch measurement.
- **"First real run against the live repo is a required verification
  step"** — reinforced *and extended* (5th instance). E2 sharpens it: the
  first real run must exercise the **installed** artifact, not the
  worktree build, or it verifies a binary no consumer will ever execute.
- **"Attended-era contracts break on first unattended contact"** —
  generalized on 2nd concordant retro. The failure class is not specific
  to *unattended*; it is **single-actor-era contracts breaking on first
  multi-actor contact**, whether the second actor is an overnight loop
  (hfiret) or a concurrent interactive session (E1 here).
