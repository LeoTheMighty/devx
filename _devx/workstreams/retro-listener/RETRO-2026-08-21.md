- **The loop is now a viable implementer for a whole epic, not just for
  isolated items.** harness-fold-in (2026-07-24/25) was the first epic the
  loop *helped* with: two of five shipped end-to-end, one abandoned at
  iteration budget and revived interactively, one wedged by infra
  misclassification. Five days later this epic ran 6/6. The difference is
  not the loop's ambition; it is that hfi's two structural fixes (PR #82
  merge-tail `phase 4:` line + iteration contract; PR #84 infra-error

- **Iteration counts cluster at the boundary of a phase's real size.**
  rtl106 (160 lines, prose + tests) took 1; rtl102 (config section) took 2;

  says only "Overnight loop item (`rtlN`); iteration history is in the
  spec's Status log on this branch." That is a deliberate loop convention
  and it worked — but see F5.

## Findings

### F1 — [high] [docs+skill] The loop's per-iteration Learnings are the highest-density evidence this project produces, and nothing was reading them

Sixteen iterations produced roughly seventy `- Learning:` lines. They are
not progress notes; they are findings, written at the moment of discovery by
the agent that hit them. A sample, all from this epic:

- *"A test that asserts inside a callback passed into `runLearnListen` is
  vacuous: the command's own catch swallows the thrown `expect()` and the
  test passes for the wrong reason."* — a whole class of false-green test.
- *"`spawn.ts`'s UUID-shaped guard is deliberately NARROWER than `queue.ts`'s
  `isSafeSessionId`… so `classifyEntry` can return 'ok' for a hand-edited id
  that `spawnRetro` then throws on — wedging the serial queue on the head
  entry across restarts."* — a cross-module invariant mismatch with a
  named failure mode.
- *"E-9's `DEVX_RETRO=1` index-before-`claude` check only passes because the
  eval hardcodes a `/tmp` marker path — the real default learn home is
  `~/.claude/devx`, so the marker path contains the substring 'claude'
  before the guard on every real machine."* — an eval that passes for the
  wrong reason.
- *"`test/learn-watch.test.ts` contains a literal NUL byte… so `file`
  reports it as `data` and plain grep silently finds nothing in it. Use
  `grep -a` — a bare grep returning zero hits is a false negative, not
  evidence the symbol is absent."*

Until this retro, the only consumer of those lines was a human happening to
read a spec. — **applied in this PR**: `LEARN.md § epic-retro-listener`
carries the four above as rows. **filed**: the general fix (a `devx` surface
that harvests `- Learning:` lines across a workstream at retro time) is a
spec, not a retro edit.

### F2 — [high] [code] A distribution step that only fires on the fresh-install path reaches almost nobody

rtl105's iteration-2 learning, quoted because the reasoning is exactly
right: *"`runInit` routes existing-devx repos to `runInitUpgrade` and
returns early, skipping the fresh-init phases — so the hook-install step
added in iteration 1 only fires on fresh init. Every repo that already has
devx (the common path, including this one) would never inherit the listener
registration, which defeats the spec Goal's 'zero per-repo setup.'"*

The fix reused the existing extensible `RepairSurface` registry rather than
duplicating logic — a `listener-hooks` entry whose detector wraps
`installHooks({dryRun:true}).action === "unchanged"` and whose repairer
wraps `installHooks()`.

Generalizable: **any new artifact `/devx-init` installs must be added to the
upgrade path, and the upgrade path is the common one.** The fresh path is
the rare case by construction — a repo only gets initialized once. —
applied in PR #108.

### F3 — [med] [code] Adding a `RepairSurface` silently breaks two kinds of existing assertion

Also rtl105: *"Adding a RepairSurface silently changes two kinds of existing
assertions: any test enumerating surfaces (`init-upgrade.test.ts`'s
`ALL_SURFACES`, which feeds `presentForAll`/`noopRepairs`) and any test
asserting an exact `added` count with the new surface left un-stubbed. Both
fail loudly, but the enumeration one is easy to miss when writing the
surface itself."*

Worth keeping because it is a *checklist* item, not an insight: the registry
is designed to be extended, and extending it has a known two-item tail. —
applied; recorded here so the next person adding a surface reads it before
the suite tells them.

### F4 — [med] [docs] The loop measured the local gate's real cost, twice, independently

rtl101: *"the full vitest run takes ~16 minutes (960s), so any iteration
that runs it should budget for that rather than expecting a quick gate."*
rtl104: *"A full `npm test` here is ~16 minutes wall-clock (135 files / 2926
tests, plus build + typecheck). Budget a whole iteration for it and poll the
buffered output file rather than expecting streamed progress."* rtl105 adds
the operational half: *"starting it and then doing diff review in the same
turn risks losing the result to a connection drop. Kick the gate off and
treat its summary line as the single thing that must be captured."*

Three independent agents in one epic arrived at the same operating
procedure. That is already memory
(`project_full_suite_exceeds_foreground_timeout`), and this epic is
corroboration from a different route — worth noting that the loop
rediscovers the same environment facts each run, which is an argument for
putting them in the iteration prompt rather than leaving each worker to
learn them. — filed.

### F5 — [med] [miss] A thin PR body is cheap for the writer and expensive for everyone downstream

All six PR bodies say the same sentence and point at the branch's spec. That
was fine while the branches existed. They are deleted now, and
`gh pr view` — the retro stage's own prescribed evidence source — returns
almost nothing for six PRs totalling +7,686 lines.

The status logs survived because they merged into `main` with the diff, so
no evidence was actually lost. But the *retro contract* says "read the
epic's PR bodies," and for this epic that step yields nothing. Either the
loop should render a real PR body (it has the material — the iteration
records), or the retro contract should say "for loop-shipped items, read the
spec status log; the PR body is a stub by design."

Tagged `(miss)` because it was invisible until someone tried to use the
artifact. — **applied in this PR**: `/devx` Stage: Retro step 1 now says
where the evidence lives for loop-shipped items.

### F6 — [low] [docs] rtl104 correctly identified an AC it could not reach, and said so instead of faking it

*"AC 6 (human smoke: real tmux + Terminal spawn, recorded in the spec status
log) is not reachable by this unattended loop — it needs a human at a
terminal, and the loop orchestrator owns the status log. Later iterations
should complete AC 1–5 + 7 and surface AC 6 as the human-owned remainder
rather than burning budget on it."*

It then did exactly that, and `9946f9` exists as the human-owned follow-up.
This is the behaviour the "attended-era contracts break on first unattended
contact" cross-epic pattern predicts an agent will get *wrong*; here it got
it right and named why. Worth recording as positive evidence — the pattern's
mitigation (make the unattended path declare what it cannot do) works. —
applied: cited in the existing cross-epic row.
