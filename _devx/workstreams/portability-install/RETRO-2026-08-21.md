## Findings

### F1 — [high] [code+docs] The suite cannot see the packaging boundary; only a real install can

Two defects shipped past a green suite and were caught only by installing
the artifact:

- **`debug-e3f1c2`** — `install:global` produced a non-executable `devx`.
  `tsc` emits `dist/cli.js` mode 644, the package `bin` points straight at
  it, and `npm i -g .` does not restore the exec bit. Every test invoked the
  CLI as `node dist/cli.js`, which does not need the bit.
- **`debug-b365ac`** — `yaml` was a devDependency while `dist/lib/config-io.js`
  imports it at runtime, so a clean packed-tarball install crashed with
  `ERR_MODULE_NOT_FOUND` on **every** invocation. The repo's own
  `node_modules` had it, so nothing local could fail.

Both are the same shape: **a property that only exists after the artifact
leaves the repo.** The fix that generalizes is pin101's, arrived at
independently — `test/skills-packaging.test.ts` runs a real
`npm pack --dry-run --json` and asserts on the manifest. That is the only
test in the suite that looks at the *package* rather than the *tree*.

This is a distinct claim from the existing "first real run against the live
repo" cross-epic pattern, which is about running against real *data*. This
one is about running the *installed* artifact. — applied: pin104 added the
chmod to `scripts/build-info.mjs` (which runs on every build, git checkout
or not) and `test/build-exec-bit.test.ts` pins it.

### F2 — [high] [code] An ownership marker must tolerate the whitespace real files carry

pin102's most load-bearing review finding: CRLF, a BOM, or trailing
whitespace on the `<!-- devx-skill v… -->` header line misclassified a
machine-owned file as user-owned — a **permanent upgrade wedge**, because
`skip-user-owned` is terminal. A Windows checkout or an editor that adds a
BOM would have frozen that user's skills forever, silently, with a
`MANUAL.md` row as the only trace.

Found by the 3-agent shape; the suite as written would not have produced a
CRLF file. — applied in PR #70 with explicit CRLF/BOM tolerance tests.

### F3 — [high] [code] Two derivations of the same value will diverge; make one read the other

pin103's load-bearing bug: the defaults provider's **mode precompute**
diverged from the skip table's `n7` inference, so production-careful repos
landed `mode=PROD` with `single-branch` + `initial_n=0` and a *false* `q32`
INTERVIEW record. The user would have been asked to confirm a decision the
system had already made differently.

Fixed by mirroring the skip table rather than re-deriving. Same family as
the cross-epic `deriveBranch` row: a value with two producers has one too
many. — applied in PR #73.

### F4 — [med] [docs] A widened union is a downstream contract change, and the spec prose will be stale

pin102 shipped a **4-member** action union (`skip-same-version` added);
the spec prose named three. The PR body called this out explicitly for
pin103's author: *"pin103 must consume the union, not the spec prose's
3-action list."*

That note is the good behaviour worth keeping — the shipping phase told the
consuming phase where the prose lies, in the artifact the consuming phase
would actually read. — applied (noted in PR #70's reviewer notes); worth
generalizing as a Phase 8 gap-filing habit: when implementation widens a
type the spec described, say so in the PR body, not only in the code.

### F5 — [med] [miss] A stale `node_modules` red-herring cost time in two separate phases

pin101 and pin102 both hit `test/tour-render.test.ts` failing from a
`node_modules` missing `diff2html` (a dep added by v2t101), and both spent
gate time on it before concluding "unrelated to this diff; `npm install`
fixed it." pin101's PR body says the file "failed identically on main."

Two phases of the same epic independently diagnosing the same environment
problem is a signal the environment check belongs *before* the gate, not
inside the diagnosis of it. (The related memory
`project_stale_dist_runtime_deps` covers the `dist/` half of this class.)
— pending: worth a one-line preflight in the `/devx` Phase 5 prose ("a
failure in a file your diff does not touch: check `npm install` before
investigating").

### F6 — [low] [docs] pin105 is the epic's honest incompleteness, and it has stayed honest

pin105 split cleanly into a scripted half (merged) and a live half (a
